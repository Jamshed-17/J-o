**Logical Volume Management** или **Управление Логическими Томами**.

**LVM** — это дополнительный слой абстракции от железа, позволяющий собрать кучи разнородных дисков в один, и затем снова разбить этот один именно так как нам хочется.
есть 3 уровня абстракции:  
1. **PV** (*Physical Volume*) — **физические тома** (это могут быть разделы или целые «неразбитые» диски)  
2. **VG** (*Volume Group*) — **группа томов** (объединяем физические тома (PV) в группу, создаём единый диск, который будем дальше разбивать так, как нам хочется)  
3. **LV** (*Logical Volume*) — **логические разделы**, собственно раздел нашего нового «единого диска» ака Группы Томов, который мы потом форматируем и используем как обычный раздел, обычного жёсткого диска.

#### Иерархия уровней LVM:

```
+--------------------------------------------------------------+
|               Logical Volumes (LV): root, home, var          |  <- Файловые 
+--------------------------------------------------------------+      системы 
                               |                                  (ext4, xfs)
+--------------------------------------------------------------+
|                     Volume Group (VG): vg_data               |  <-      Пул 
+--------------------------------------------------------------+     хранения 
            /                                      \          (состоит из PE)
+-----------------------+              +-----------------------+
|  Physical Volume (PV) |              |  Physical Volume (PV) |  <- Инициал- 
|       /dev/sdb        |              |       /dev/sdc1       | -изированные 
+-----------------------+              +-----------------------+        диски
```

1. **Physical Volume (PV) — Физический том:**
    - Базовый физический блочный накопитель (`/dev/sdb`) или его раздел (`/dev/sdc1`).    
    - При инициализации на устройство записывается специальный заголовок метаданных LVM.

2. **Volume Group (VG) — Группа томов:**
    - Объединение одного или нескольких PV в единый виртуальный накопитель (пул).
    - Пространство VG делится на блоки фиксированного размера — **Physical Extents (PE)** (по умолчанию 4 МБ).

3. **Logical Volume (LV) — Логический том:**
    - Виртуальный раздел, нарезаемый из доступных PE внутри группы томов (VG).
    - Для операционной системы отображается как блочное устройство (пути: `/dev/mapper/<vg_name>-<lv_name>` или `/dev/<vg_name>/<lv_name>`), на котором создаётся файловая система (ext4, XFS и др.).

4. **Logical Extent (LE) / Physical Extent (PE):**
    - Минимальная единица распределения дискового пространства. При выделении LV связывает логические экстенты (LE) с физическими экстентами (PE).

### Справочник и шпаргалка по командам

Команды LVM стандартизированы по префиксам уровней: `pv*` (диски), `vg*` (группы), `lv*` (разделы).

|**Действие**|**Physical Volume (PV)**|**Volume Group (VG)**|**Logical Volume (LV)**|
|---|---|---|---|
|**Краткий список**|`pvs`|`vgs`|`lvs`|
|**Детальный статус**|`pvdisplay`|`vgdisplay`|`lvdisplay`|
|**Создание**|`pvcreate <диск>`|`vgcreate <имя_vg> <pv1> [pv2]`|`lvcreate -n <имя_lv> -L <размер> <имя_vg>`|
|**Расширение**|`pvresize <диск>`|`vgextend <имя_vg> <pv>`|`lvextend -L +<размер> <путь_к_lv>`|
|**Уменьшение**|—|`vgreduce <имя_vg> <pv>`|`lvreduce -L -<размер> <путь_к_lv>` _(опасно)_|
|**Удаление**|`pvremove <диск>`|`vgremove <имя_vg>`|`lvremove <путь_к_lv>`|

### Пошаговые сценарии работы

#### 1. Подготовка и создание стека LVM с нуля

1. **Инициализация физических дисков в PV:**
```
pvcreate /dev/sdb /dev/sdc
```

2. **Создание группы томов из дисков:**
```
vgcreate vg_data /dev/sdb /dev/sdc
```

3. **Создание логического тома:**
- По фиксированному размеру:
```
lvcreate -L 50G -n lv_storage vg_data
```

- На весь свободный объем VG:
```
lvcreate -l 100%FREE -n lv_storage vg_data
```

4. **Создание файловой системы и монтирование:**
```
mkfs.ext4 /dev/vg_data/lv_storage
mkdir -p /mnt/storage
mount /dev/vg_data/lv_storage /mnt/storage
```
_Для постоянного монтирования добавьте запись с UUID раздела в `/etc/fstab`_

#### 2. Расширение дискового пространства на лету

Расширение выполняется без размонтирования файловой системы.

1. **Если в текущей группе (VG) достаточно свободного места:**
```
# Добавить 20 ГБ и сразу изменить размер файловой системы:
lvextend -r -L +20G /dev/vg_data/lv_storage
```
_(Флаг `-r` автоматически запускает `resize2fs` для ext4 или `xfs_growfs` для XFS)._

2. **Если нужно предварительно расширить саму группу (VG) новым диском:**
```
pvcreate /dev/sdd
vgextend vg_data /dev/sdd
lvextend -r -l +100%FREE /dev/vg_data/lv_storage
```

#### 3. Снимки состояния (LVM Snapshots)

Снимки фиксируют состояние тома на момент создания по принципу Copy-on-Write (CoW). Расходуют место только на изменяемые блоки данных.
1. **Создание снапшота:**
```
lvcreate -L 10G -s -n snap_storage /dev/vg_data/lv_storage
```

2. **Откат к снимку:**
```
umount /mnt/storage
lvconvert --merge /dev/vg_data/snap_storage
mount /dev/vg_data/lv_storage /mnt/storage
```
_(Снимок после успешного слияния удаляется автоматически)._

#### 4. Замена или вывод диска из эксплуатации без простоя
Если диск `/dev/sdb` начал сыпаться или его нужно освободить:
1. Добавьте новый диск в ту же группу:
```
pvcreate /dev/sde
vgextend vg_data /dev/sde
```

2. Перенесите данные (экстенты) со старого диска на новый:
```
pvmove /dev/sdb /dev/sde
```

3. Исключите старый диск из VG и очистите метаданные LVM:
```
vgreduce vg_data /dev/sdb
pvremove /dev/sdb
```

#### 5. Корректное удаление компонентов LVM
Удаление всегда выполняется в обратном порядке:

1. Размонтировать файловую систему: `umount /mnt/storage`
2. Удалить логический том: `lvremove /dev/vg_data/lv_storage`
3. Удалить группу томов: `vgremove vg_data`
4. Удалить разметку PV с дисков: `pvremove /dev/sdb /dev/sdc`


> [!danger]
>  **Критическое замечание по уменьшению томов (Shrinking):**
>  
>  
> 
>  - Файловая система **XFS не поддерживает уменьшение размера**.
>  
>  
>  
>  - Файловую систему **ext4 уменьшать можно**, но только в отмонтированном состоянии (`umount`), предварительно выполнив `e2fsck -f`, затем уменьшив саму файловую систему через `resize2fs`, и только после этого выполняя `lvreduce`. Ошибка в расчетах приведет к потере данных.
